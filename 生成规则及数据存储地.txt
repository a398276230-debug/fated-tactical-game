<战前资源推演>
新战斗使用以下 `<battle_init>` 版本 1 描述符。先登记新角色的 `<char_info>`，然后输出一个战斗块。

<battle_init>
battle|1|training-yard|演武场对练|terrain
unit|p1|blue|mvu:主角|主角显示名|2,2
unit|a1|blue|mvu:关系列表/队友A|队友A|3,2
unit|e1|red|char_info|敌人姓名|7,7
</battle_init>

- 首行格式为 `battle|1|战局ID|场景标题|flat或terrain`，可在末尾追加 `|seed`。种子为 0 至 4294967295 的整数。省略时由战局 ID 推导。
- 每个参战者单独占一行，格式为 `unit|单位ID|blue或red|来源|显示名|x,y`。战局 ID 和单位 ID 使用 ASCII 字母、数字、下划线或连字符。单位 ID 与起点各自唯一，坐标为 0 至 9 的整数。字段内勿使用竖线或换行。
- `flat` 生成平地，`terrain` 由沙盘按种子布置高台、坡道与墙体。角色起点不会生成墙体。
- `mvu:` 后填写从 `stat_data` 开始的精确键路径，主角使用 `mvu:主角`，同伴按实际关系列表路径填写。`char_info` 行的显示名须与角色登记名一致。数值、装备、技能与状态从来源读取，战斗块只声明名册和站位。

缺失体长依据时按中型 1.7m 处理。主模型不输出装备、属性、资源或地形 JSON。旧战斗存档由沙盘兼容读取。
</战前资源推演>

<战斗协议>
核心原则:
  1. 武装冲突与正式战斗由外部战术沙盘统一演算胜负、数值、状态与伤亡。<% if (!destinyImmersiveMode()) { %><%- destinyWiVar('系统名') %>与<%- destinyWiVar('系统核心名') %>仅作旁观记录，战报结果由沙盘裁定。<% } %>
  2. 叙事严格遵循沙盘战报的客观事实，按战报既定的命中评级、伤害数值、状态施加、退场与胜负结论展开描写。

两阶段工作流:
  一、开战触发（沙盘初始化）:
    - 当剧情进入明确敌对交锋时，先完成必要新参战者的 `<char_info>` 登记，再按 `<战前资源推演>` 输出 `<battle_init>` 数据块。
    - 叙事停在交锋前夕或起手瞬息（描写站位、地形、掩体、对峙张力与起手姿态），交由沙盘接管演算。

  二、战报演绎（基于沙盘战报描写与结算）:
    - 收到沙盘演算战报（回合行动记录、先手顺序、命中评级、伤害、状态变化、伤亡/昏迷/战意溃散及最终胜负）后，依战报时间线进行文学化战斗描写：
      - 行动与空间: 忠实还原先手顺序、位移包抄、高低差、掩体遮蔽与损毁、互动点触发。
      - 命中与意图: 依战报评级（失手/擦伤/勉强/有效/平暴击/强暴击/超暴击）与意图层级（常规/机能限制/核心要害/抹杀/概念破碎）匹配动作质感；意图受阻或目标 `HP > 0` 时描写为偏折、硬抗或非致命受创。
      - 生死与士气: `HP > 0` 即为存活；`nonLethal` 留 1 HP 表现击晕或制服；战意动摇/溃散（`shaken`/`routed`/逃跑/投降）表现敌方士气崩溃；触发亡语（`deathrattle`）时按战报描写死后余波。
      - 战后结算: 若战报已确认战斗结束，在叙事收尾时依战报损耗与战果更新 `<UpdateVariable>`，按 `<经验值获取规则>` 与战利品规则结算奖励并生成对应 `<item_info>`。

叙事质感参考:
  - 集群单位（`swarm`）: 描写群体协同冲锋、阵型折损与减员散乱。
  - 巨兽单位（`mc≥2`）: 突出庞大体型带来的压迫感、广域横扫与地形震动。
</战斗协议>
